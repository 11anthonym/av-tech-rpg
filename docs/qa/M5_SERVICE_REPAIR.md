# M5-B — paid Conshohocken service call

Continue a clean first-day career through the morning service briefing. Review
the ticket at the shop workbench, drive Van #3, and check in using the room phone.
Inspect the display, credenza path and replacement kit. Findings unlock repair
methods; the room phone also offers the client's symptom timeline.

At the display choose a repair approach. Carry each replacement component from
the kit to the display and install it. Installed components leave the staging
bench, carrying uses the existing animated pose, and the screen/mount show
progress. Handle known room pressure and visible incidents at the credenza.
Choose a full, quick or unverified handoff test at the display, then close out
with the client using the phone. Return to the shop and read the paid report.

## Rules and persistence

- Canonical component/method/evidence/condition IDs, unlocks, minutes, field
  checks, tool bonuses, pressure responses, recovery choices, $96 wages and
  40–58 XP come from the original 2D service call. The generated bridge reads
  actual data and pure response-option functions; parity tests execute the
  original runtime through negotiated/hardware and full/unverified replays.
- Time, energy, burnout, professional standing, careful finishes, workmanship,
  named callback causes and assignment routing persist. The shop follow-up
  states which saved cause creates callback cleanup instead of future service.
- Quick condition rolls use the saved seed rather than fresh `Math.random`.
  This intentional persistence change prevents rerolling an incident by reload.
  Appointment and final-confidence rolls retain the original seed salts.
- Version 6 writes `av-tech-rpg-3d-dev-v6`. Versions 1–5 remain readable; old
  namespace bytes and `av-tech-rpg-save-v1` remain untouched. V5 diagnosis is
  reconstructed without charging prior effort again.
- The first-day career is archived at service preparation and remains subject
  to the strict M4 validator. Current service results are validated by replaying
  saved domain actions against that archive. Repeated install, test and paid
  closeout actions cannot charge or reward twice.
